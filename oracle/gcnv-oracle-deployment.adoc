= Fluxo de trabalho do Google Cloud NetApp Volumes para implantar alta disponibilidade do Oracle Database 26ai
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Utilize o armazenamento em blocos iSCSI do Google Cloud NetApp Volumes para implantar o Oracle Database 26ai de alta disponibilidade com o Oracle Data Guard no Google Compute Engine. Este fluxo de trabalho orienta você pelas opções de implantação, provisionamento de infraestrutura, instalação do software Oracle e configuração de alta disponibilidade, aproveitando a replicação na camada de storage do GCNV para inicialização acelerada do standby.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-1.png["Um"]link:gcnv-oracle-solution-architecture.html["Analise a arquitetura da solução"]
[role="quick-margin-para"]
Compreenda a arquitetura do Google Cloud NetApp Volumes para alta disponibilidade do Oracle Database 26ai, incluindo o design de armazenamento em bloco iSCSI GCNV, a integração com o Data Guard e a topologia de storage.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-2.png["Dois"]link:gcnv-oracle-deployment-options.html["Analise as opções e os requisitos de implementação"]
[role="quick-margin-para"]
Compare os níveis de implantação, desde desenvolvimento/teste até HA em produção, e confirme os pré-requisitos de infraestrutura, acesso e software.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-3.png["Três"]link:gcnv-oracle-access-and-apis.html["Verifique o acesso e as APIs"]
[role="quick-margin-para"]
Confirme o acesso necessário, a capacitação de API, os pré-requisitos de rede e a sincronização de horário.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-4.png["Quatro"]link:gcnv-oracle-provision-compute.html["Provisionar instâncias do Google Compute Engine"]
[role="quick-margin-para"]
Crie máquinas virtuais para o banco de dados primário, o banco de dados em espera e o observador Fast-Start Failover.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-5.png["Cinco"]link:gcnv-oracle-provision-storage.html["Provisionar storage iSCSI GCNV"]
[role="quick-margin-para"]
Crie pools de armazenamento GCNV e volumes iSCSI, configure multipath e configure grupos de discos ASM.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-6.png["Seis"]link:gcnv-oracle-install-software.html["Instale o Oracle Grid Infrastructure e o Oracle Database 26ai"]
[role="quick-margin-para"]
Instale o software Oracle Grid Infrastructure e Oracle Database 26ai em ambos os hosts de banco de dados.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-7.png["Sete"]link:gcnv-oracle-primary-database.html["Crie o banco de dados principal"]
[role="quick-margin-para"]
Crie o banco de dados Oracle primário com armazenamento ASM e configure o Oracle Restart.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-8.png["Oito"]link:gcnv-oracle-standby-database.html["Crie o banco de dados de espera"]
[role="quick-margin-para"]
Inicialize o banco de dados standby usando replicação GCNV, snapshots ou clones, depois registre-o no Oracle Restart. Todas as camadas de alta disponibilidade (HA) concluem esta etapa.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-9.png["Nove"]link:gcnv-oracle-standby-finalize-dg.html["Finalizar o banco de dados standby para o Data Guard"]
[role="quick-margin-para"]
Crie logs de redo em espera, habilite o flashback, ative o envio de redo e verifique o estado do Data Guard. *Específico da camada:* necessário apenas para Prod HA (Data Guard + FSFO) tier.

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-10.png["Dez"]link:gcnv-oracle-data-guard.html["Configurar o Data Guard Broker e o Fast-Start Failover"]
[role="quick-margin-para"]
Habilite o broker, crie a configuração do Data Guard, habilite o FSFO e configure o Observer. *Específico da camada:* Necessário apenas para a camada de Prod HA (Data Guard + FSFO).
