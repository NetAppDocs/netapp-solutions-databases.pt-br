[role="lead"]
Implante o SQL Server 2025 no Windows Server 2025 com bancos de dados de usuário, logs de transações, TempDB e backups em compartilhamentos SMB 3 com disponibilidade contínua em um sistema AFF da NetApp. Este procedimento inclui a configuração da SVM, dos volumes e dos compartilhamentos do ONTAP, a instalação do SQL Server e a proteção dos bancos de dados com o SnapCenter.



[[scope]]
[[intro-scope]]
== Escopo

Este procedimento implementa uma instância independente do SQL Server 2025 em um único host do Windows Server 2025, com bancos de dados de usuário, logs de transação, TempDB e backups em compartilhamentos SMB 3 com disponibilidade contínua (CA). O mesmo design de storage se aplica a instâncias de cluster de failover (FCI) do SQL Server e a grupos de disponibilidade Always On, mas a configuração específica do cluster não é abordada. O ajuste e o dimensionamento do SQL Server também estão fora do escopo. Para conhecer os benefícios, os componentes da solução, os princípios de design e uma explicação de como a disponibilidade contínua funciona, consulte link:sql-smb3-aff-overview.html["Saiba mais sobre o SQL Server 2025 no NetApp AFF com disponibilidade contínua do SMB 3"].



[[audience]]
[[intro-audience]]
== Público

Este procedimento destina-se a:

* *Administradores de armazenamento*, que configuram o cluster do ONTAP, a SVM, os volumes e os compartilhamentos SMB.
* *Administradores do Windows e do Active Directory*, que preparam o host do Windows Server 2025, as contas de serviço e a rede.
* *Administradores de banco de dados*, que instalam e configuram o SQL Server 2025 e configuram backup e recuperação.


Pressupõe-se conhecimento básico de administração do ONTAP System Manager, do Windows Server e do SQL Server.

[[prerequisites]]
== Pré-requisitos

Certifique-se de atender aos seguintes requisitos antes de começar:

.NetApp ONTAP
* O par de HA AFF está instalado, e o cluster está configurado e saudável.
* A licença CIFS (SMB) está instalada. Ela está incluída no ONTAP One.
* Existe pelo menos um agregado de dados (camada local) em cada nó.
* O horário é sincronizado entre o cluster e o Active Directory por meio do NTP. O desvio máximo permitido no relógio Kerberos é de 5 minutos.
* As portas de rede de dados, o domínio de broadcast e, opcionalmente, as VLANs para as LIFs SMB estão configurados.


.O Active Directory e DNS
* Um domínio do Active Directory está disponível, e os servidores DNS podem ser acessados a partir das LIFs de dados do SVM.
* Você possui uma conta com permissão para criar objetos de computador na Unidade Organizacional (OU) de destino, para o servidor CIFS.
* Uma conta de usuário de domínio dedicada como conta de serviço está disponível para os serviços do SQL Server Database Engine e do SQL Server Agent.



IMPORTANT: O SQL Server deve ser executado em uma *conta de domínio* quando seus arquivos estiverem em um compartilhamento SMB. Contas virtuais internas (`NT SERVICE\MSSQLSERVER`) e contas locais não podem receber permissão para acessar um compartilhamento de arquivos remoto.

.Servidor Windows
* Windows Server 2025 (Desktop Experience) está instalado, atualizado e integrado ao domínio.
* A mídia de instalação do SQL Server 2025 (ISO) e uma chave de produto válida (ou uma edição gratuita) estão disponíveis.


.Requisitos e restrições de SMB para o SQL Server no ONTAP
* O SMB 3.0 ou posterior deve estar habilitado na SVM.
* Todos os volumes que hospedam compartilhamentos CA devem usar o estilo de segurança *NTFS* e devem ter sido NTFS desde o início.
* SMB Direct (RDMA) não é suportado.
* O ReFS não é suportado. O ONTAP (WAFL) fornece o sistema de arquivos para os compartilhamentos.

== Etapa 2: criar e configurar a máquina virtual de storage (SVM)

Use uma SVM dedicada para o SQL Server. A SVM ingressa no Active Directory como um servidor CIFS e fornece uma LIF de dados SMB em cada nó do par de HA.

.Passos
. Crie a SVM com System Manager ou a CLI:
+
[role="tabbed-block"]
====
.System Manager
--
.. No System Manager, acesse o menu:Cluster[VMs de armazenamento] e clique em *+ Adicionar*.
+
.Mostrar exemplo
[%collapsible]
=====
image:sql25_smb_bp_006.png["Cluster > VMs de armazenamento > Adicionar"]

=====
.. Insira o *nome da VM de armazenamento* `a50-sql`. Em *Protocolo de acesso*, selecione a guia *SMB/CIFS, NFS, S3* e selecione *Habilitar SMB/CIFS*.
+
.Mostrar exemplo
[%collapsible]
=====
image:sql25_smb_bp_007.png["Adicionar VM de storage: nome e protocolo"]

=====
+

NOTE: O nome da VM de storage é o nome SMB do servidor CIFS.

.. Insira as informações do Active Directory (domínio, nome e senha do administrador e OU) e as informações de DNS (domínio DNS e servidores de nomes).
.. Em *interface de rede*, configure uma LIF de dados em *cada* nó.
+

TIP: Uma LIF por nó fornece ao SQL Server um caminho direto (local) para cada nó, sendo um pré-requisito para o SMB multicanal e para failover sem interrupções. Utilize portas de 25 GbE ou mais rápidas e o mesmo MTU de ponta a ponta.

+

NOTE: Você deve registrar essas interfaces de rede em seu servidor DNS. Para obter detalhes, consulte https://docs.netapp.com/us-en/ontap-system-manager-classic/smb-config/task_mapping_smb_server_dns_server.html["Mapeie o servidor SMB para o servidor DNS"^].

.. Clique em *Salvar*. O System Manager cria a SVM, o volume raiz, as LIFs e a configuração de DNS, e integra o servidor CIFS ao domínio.
.. Verifique o volume raiz da SVM (`a50_sql_root` no laboratório). Ele deve usar o estilo de segurança *NTFS*, caso contrário os compartilhamentos SMB não funcionarão. Vá para menu:Storage[Volumes], selecione o volume raiz e clique em *Edit* para revisar suas configurações.
+
.Mostrar exemplo
[%collapsible]
=====
image:sql25_smb_bp_012.png["Editar o volume raiz da SVM a50_sql_root"]

=====


--
.ONTAP CLI
--
Os comandos a seguir criam a mesma configuração a partir da CLI. Substitua os valores de espaço reservado entre sinais de maior e menor.

[source, console]
----
cluster::> vserver create -vserver a50-sql -rootvolume a50_sql_root -aggregate <aggr_node1> -rootvolume-security-style ntfs

cluster::> vserver modify -vserver a50-sql -allowed-protocols cifs

cluster::> network interface create -vserver a50-sql -lif a50-sql_smb_n1 -service-policy default-data-files -home-node <node1> -home-port <port> -address 192.168.175.138 -netmask <netmask>
cluster::> network interface create -vserver a50-sql -lif a50-sql_smb_n2 -service-policy default-data-files -home-node <node2> -home-port <port> -address 192.168.175.139 -netmask <netmask>

cluster::> vserver services name-service dns create -vserver a50-sql -domains sapcc.stl.netapp.com -name-servers <dns1>,<dns2>

cluster::> vserver cifs create -vserver a50-sql -cifs-server A50-SQL -domain sapcc.stl.netapp.com -ou CN=Computers
----
--
====
. [[svm-smb-options,Configure as opções do servidor SMB]]Configure as opções do servidor SMB. Verifique se as opções de SMB necessárias para o SQL Server estão habilitadas na SVM:
+
[source, console]
----
cluster::> set -privilege advanced
cluster::*> vserver cifs options show -vserver a50-sql -fields smb3-enabled,is-multichannel-enabled,is-large-mtu-enabled,copy-offload-enabled,shadowcopy-enabled
cluster::*> vserver cifs options modify -vserver a50-sql -smb3-enabled true -is-multichannel-enabled true -is-large-mtu-enabled true -copy-offload-enabled true -shadowcopy-enabled true
cluster::*> set -privilege admin
----
+
[cols="1,3"]
|===
| Opção | Propósito 


| `smb3-enabled` | O SMB 3.x é necessário para compartilhamentos com disponibilidade contínua. 


| `is-multichannel-enabled` | O SMB multicanal usa várias conexões TCP e caminhos de rede para maior taxa de transferência e resiliência. 


| `is-large-mtu-enabled` | Permite leituras e gravações SMB de até 1 MB. 


| `copy-offload-enabled` | Descarregamento de cópia ODX; as cópias são executadas dentro do sistema de storage. 


| `shadowcopy-enabled` | VSS remoto para compartilhamentos SMB. Necessário para aplicativos de backup que usam VSS para compartilhamentos SMB. 
|===
. Verifique se o servidor CIFS está registrado no DNS e se pode ser resolvido a partir do host do SQL Server:
+
[source, powershell]
----
PS C:\> Resolve-DnsName a50-sql.sapcc.stl.netapp.com
----

== Passo 4: ajuste as configurações do volume

Revise e ajuste as configurações de espaço e de Snapshot de cada volume do SQL Server.

.Passos
. Na lista de volumes, passe o cursor sobre o volume desejado e clique no ícone de lápis (*Editar*).
+
.Mostrar exemplo
[%collapsible]
====
image:sql25_smb_bp_023.png["Ícone de edição na lista de volumes"]

====
. Configure o volume da seguinte forma (mostrado para `sql1_data`):
+
** *Habilitar thin provisioning*: selecionado
** *Redimensionar automaticamente*: selecionado, *Modo de crescimento automático*: *Crescer*, *Tamanho máximo*: por exemplo `1.3 TiB` (cerca de 125–130 % do tamanho do volume)
** *Habilitar reserva fracionária (100%)*: desmarcado
** *Tipo de segurança*: `NTFS`
** *reserva do Snapshot %*: `5` (`0` para `sql1_tempdb`)
** *Agendar snapshots*: desmarcado. Snapshots que não são consistentes com a aplicação não têm utilidade para o SQL Server; use o NetApp SnapCenter em vez disso.
** *Exibir o diretório de snapshots para os clientes*: opcional (o laboratório o deixou selecionado; desmarcá-lo oculta `~snapshot` do compartilhamento)
+
Clique em *Salvar* e repita para `sql1_log`, `sql1_tempdb` e `sql1_backups`.

+
.Mostrar exemplo
[%collapsible]
====
image:sql25_smb_bp_024.png["Editar configurações do volume sql1_data,width=450"]

====




[source, console]
----

[[step-6-prepare-windows-server-2025]]
[[windows-prep]]
== Etapa 6: preparar o Windows Server 2025

Execute os seguintes passos no host do SQL Server `{host}` como administrador de domínio.

.Passos
. Verifique se o servidor está ingressado no domínio e se o servidor CIFS pode ter o nome resolvido (consulte <<svm-smb-options>>).
. Certifique-se de que a conta de serviço do SQL Server exista no Active Directory, por exemplo `SAPCC\sql1admin`. Use a mesma conta para o Mecanismo de Banco de Dados e para o SQL Server Agent, ou use uma conta separada para cada um. Independentemente da sua escolha, conceda a cada conta acesso a todos os quatro compartilhamentos.
. Testar o acesso aos compartilhamentos no contexto de segurança da conta de serviço:
+
[source, powershell]
----
PS C:\> runas /user:SAPCC\sql1admin "cmd /c dir \\a50-sql\sql1_data && echo test > \\a50-sql\sql1_data\write-test.txt && del \\a50-sql\sql1_data\write-test.txt"
----
. Abra a porta do SQL Server no firewall do Windows:
+
[source, powershell]
----
PS C:\> New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----
. Verifique a conexão SMB com a SVM. O dialeto deve ser 3.x e `ContinuouslyAvailable` deve ser `True`:
+
[source, powershell]
----
PS C:\> dir \\a50-sql\sql1_data | Out-Null
PS C:\> Get-SmbConnection -ServerName a50-sql | Format-Table ServerName,ShareName,Dialect,ContinuouslyAvailable,Encrypted,Signed
PS C:\> Get-SmbMultichannelConnection -ServerName a50-sql
----



NOTE: Por padrão, o Windows Server 2025 exige assinatura SMB para todas as conexões SMB de saída. O ONTAP oferece suporte à assinatura SMB e a negocia automaticamente. A assinatura adiciona sobrecarga de CPU em ambas as extremidades, portanto, inclua-a em seus testes de desempenho. Não desative a assinatura sem uma revisão de segurança.

== Etapa 8: verifique a instalação e crie um banco de dados

Crie um banco de dados de teste com o SQL Server Management Studio (SSMS) e verifique se seus arquivos de dados e de log estão nos compartilhamentos SMB. Opcionalmente, confirme no ONTAP se os arquivos abertos utilizam disponibilidade contínua.

Insira um nome para o banco de dados (`SQ1` no laboratório), defina os tamanhos iniciais dos arquivos e clique em *OK*. Os caminhos dos arquivos de dados e de log são definidos por padrão para `+\\a50-sql\sql1_data+` e `+\\a50-sql\sql1_log+`.
+
.Mostrar exemplo

====
. O novo banco de dados aparece no *Object Explorer*.
+
.Mostrar exemplo
[%collapsible]

. Verifique a localização dos arquivos com T-SQL:

[source, sql]

SELECT DB_NAME(database_id) AS database_name,
       type_desc,
       name AS logical_name,
       physical_name,

[[use-an-ontap-cli-script-to-configure-the-storage-in-one-pass]]
== Use um script da CLI do ONTAP para configurar o armazenamento de uma só vez

O script a seguir contém a configuração de storage deste procedimento. Substitua os valores entre colchetes angulares antes de executá-lo.

[source, console]
----
# --- SVM -----------------------------------------------------------------
vserver create -vserver a50-sql -rootvolume a50_sql_root -aggregate <aggr_node1> -rootvolume-security-style ntfs
vserver modify -vserver a50-sql -allowed-protocols cifs

network interface create -vserver a50-sql -lif a50-sql_smb_n1 -service-policy default-data-files -home-node <node1> -home-port <port> -address 192.168.175.138 -netmask <netmask>
network interface create -vserver a50-sql -lif a50-sql_smb_n2 -service-policy default-data-files -home-node <node2> -home-port <port> -address 192.168.175.139 -netmask <netmask>

vserver services name-service dns create -vserver a50-sql -domains sapcc.stl.netapp.com -name-servers <dns1>,<dns2>
vserver cifs create -vserver a50-sql -cifs-server A50-SQL -domain sapcc.stl.netapp.com -ou CN=Computers

set -privilege advanced
vserver cifs options modify -vserver a50-sql -smb3-enabled true -is-multichannel-enabled true -is-large-mtu-enabled true -copy-offload-enabled true -shadowcopy-enabled true
set -privilege admin

# --- Volumes -------------------------------------------------------------
volume create -vserver a50-sql -volume sql1_data    -aggregate <aggr_node1> -size 1TB   -security-style ntfs -junction-path /sql1_data    -space-guarantee none -fractional-reserve 0 -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 1.3TB
volume create -vserver a50-sql -volume sql1_log     -aggregate <aggr_node2> -size 512GB -security-style ntfs -junction-path /sql1_log     -space-guarantee none -fractional-reserve 0 -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 650GB
volume create -vserver a50-sql -volume sql1_tempdb  -aggregate <aggr_node2> -size 500GB -security-style ntfs -junction-path /sql1_tempdb  -space-guarantee none -fractional-reserve 0 -percent-snapshot-space 0 -snapshot-policy none -autosize-mode grow -max-autosize 650GB
volume create -vserver a50-sql -volume sql1_backups -aggregate <aggr_node1> -size 2000GB -security-style ntfs -junction-path /sql1_backups -space-guarantee none -fractional-reserve 0 -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 2600GB

# --- CA shares -----------------------------------------------------------
vserver cifs share create -vserver a50-sql -share-name sql1_data    -path /sql1_data    -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_log     -path /sql1_log     -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_tempdb  -path /sql1_tempdb  -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_backups -path /sql1_backups -share-properties oplocks,browsable,changenotify,continuously-available

# --- Share permissions (repeat for each share) ----------------------------
vserver cifs share access-control create -vserver a50-sql -share sql1_data -user-or-group SAPCC\sql1admin -permission Full_Control
vserver cifs share access-control delete -vserver a50-sql -share sql1_data -user-or-group Everyone

# --- Verification ----------------------------------------------------------
vserver cifs show -vserver a50-sql
vserver cifs share show -vserver a50-sql -fields share-name,path,share-properties
vserver cifs session file show -vserver a50-sql -fields share,path,continuously-available
----

TIP: Distribua os volumes entre os agregados de ambos os nós, por exemplo dados e backup no nó 1 e log e TempDB no nó 2. Isso utiliza os recursos de ambos os controladores.
