= Implante o SQL Server 2025 no NetApp AFF usando LUNs iSCSI
:allow-uri-read: 


[role="lead"]
Implante o SQL Server 2025 no Windows Server 2025 com bancos de dados de usuário, logs de transações, TempDB e backups de log em LUNs iSCSI em um sistema AFF da NetApp. Este procedimento inclui configurar o iSCSI na SVM do ONTAP, o grupo de iniciadores e as LUNs, o iniciador iSCSI do Windows, o MPIO e os discos, além de instalar o SQL Server.



[[scope]]
[[intro-scope]]
== Escopo

Este procedimento implementa uma instância independente do SQL Server 2025 em um único host Windows Server 2025, com bancos de dados de usuário, logs de transações, TempDB e backups de log em LUNs iSCSI. O mesmo design de storage se aplica a instâncias de cluster de failover (FCI) do SQL Server e a grupos de disponibilidade Always On, mas a configuração específica do cluster não é abordada. O ajuste de desempenho e o dimensionamento do SQL Server também estão fora do escopo. Para conhecer os benefícios, os componentes da solução, os princípios de design, uma explicação de como o multipath funciona e a proteção de dados com o NetApp Console Backup and Recovery, veja link:sql-iscsi-aff-overview.html["Saiba mais sobre o SQL Server 2025 no NetApp AFF com LUNs iSCSI"].



[[audience]]
[[intro-audience]]
== Público

Este procedimento destina-se a:

* *Administradores de armazenamento*, que configuram o cluster do ONTAP, a SVM, as LIFs iSCSI, o grupo de iniciadores e as LUNs.
* *Administradores do Windows*, que preparam o host do Windows Server 2025, o iniciador iSCSI, o MPIO e os discos.
* *Administradores de banco de dados*, que instalam e configuram o SQL Server 2025 e configuram backup e recuperação.


Pressupõe-se conhecimento básico de administração do ONTAP System Manager, do Windows Server e do SQL Server.

TIP: Use LUNs adicionais em controladores diferentes para arquivos de dados secundários (.ndf) a fim de distribuir a carga.



[[prerequisites]]
== Pré-requisitos

Certifique-se de atender aos seguintes requisitos antes de começar:

.NetApp ONTAP
* O par de HA AFF está instalado, e o cluster está configurado e saudável.
* A licença iSCSI está instalada. Ela está incluída no ONTAP One.
* Existe pelo menos um agregado de dados (camada local) em cada nó.
* A SVM existe. Neste procedimento, você usa a SVM existente `{svm}`; adiciona iSCSI a ela. Para criar uma SVM dedicada para SAN, use menu:Cluster[VMs de armazenamento > Adicionar] e selecione *iSCSI* como protocolo de acesso.
* As portas de rede de dados, o domínio de broadcast e, opcionalmente, as VLANs para as LIFs iSCSI estão configurados. No laboratório, o domínio de broadcast `MT9000` usa jumbo frames.
* O horário é sincronizado entre o cluster, o host e o Active Directory por meio do NTP.


.Rede
* O host do SQL Server tem pelo menos uma, de preferência duas, placas de rede dedicadas para iSCSI na sub-rede iSCSI ou VLAN.
* O MTU é o mesmo de ponta a ponta (NIC do host, switches, portas do ONTAP). Verifique os jumbo frames com `ping -f -l 8972 <LIF-IP>` a partir do host.


.Servidor Windows
* Windows Server 2025 (Desktop Experience) está instalado, atualizado e integrado ao domínio.
* O NetApp Windows Host Utilities em uma versão compatível com o Windows Server 2025 está disponível (consulte o  https://imt.netapp.com/matrix/["NetApp Ferramenta de Matriz de Interoperabilidade (IMT)"^]).
* A mídia de instalação do SQL Server 2025 (ISO) e uma chave de produto válida (ou uma edição gratuita) estão disponíveis.



NOTE: Ao contrário dos compartilhamentos de arquivos SMB, os LUNs não exigem uma conta de domínio para o serviço do SQL Server. As contas virtuais padrão (`NT Service\MSSQLSERVER`) podem ser usadas. Uma conta de domínio ou gMSA ainda é recomendada se a instância precisar de acesso à rede, por exemplo, para fazer backup em um compartilhamento de arquivos ou para autenticação Kerberos.

Adicione o protocolo iSCSI à SVM e crie duas LIFs iSCSI em cada nó do par de HA.

.Passos
. Habilite iSCSI na SVM e crie as LIFs iSCSI com System Manager ou a CLI:
+
[role="tabbed-block"]
====

--
.. Abra um navegador da web e conecte-se ao ONTAP System Manager em `+https://<cluster-management-IP>+`. Faça login com a conta de administrador do cluster.
.. Acesse o menu:Cluster[VMs de armazenamento], clique na SVM `{svm}` e abra a guia *Settings*. Em *Protocols*, o bloco *iSCSI* mostra *Not configured*. Clique no ícone de engrenagem no bloco *iSCSI*.
+
.Mostrar exemplo
[%collapsible]
=====
image:sql25_iscsi_bp_004.png["Configurações da VM de armazenamento a50-sql com iSCSI não configurado,largura=800"]

=====
.. Na caixa de diálogo *Configure iSCSI*, crie as interfaces de rede iSCSI. O System Manager recomenda duas interfaces de rede por nó. Insira os seguintes valores:
+
*** Nó `{node1}`: endereço IP `192.168.175.134`, máscara de sub-rede `24`, *domínio de broadcast e porta* `MT9000`
*** Selecione *Usar a mesma máscara de sub-rede, gateway e domínio de broadcast para todas as seguintes interfaces*.
*** Segunda interface em `{node1}`: `192.168.175.135`
*** Nó `{node2}`: `192.168.175.136` e `192.168.175.137`
+
Clique em *Salvar*.

+

+
.Mostrar exemplo
[%collapsible]

image:sql25_iscsi_bp_005.png["Caixa de diálogo Configurar iSCSI com duas LIFs por nó, largura=800"]

=====


.. O System Manager cria o serviço iSCSI e as quatro LIFs. O bloco *iSCSI* agora exibe *Ativado*, o *nome do nó de destino* (`{tgt-iqn}`) e o *alias de destino* `{svm}`. Anote o nome do nó de destino; você precisará dele para verificar a conexão do host.
+
.Mostrar exemplo
[%collapsible]
=====
image:sql25_iscsi_bp_006.png["iSCSI habilitado com nome do nó de destino e alias,width=800"]

=====


--
.ONTAP CLI
--
Os comandos a seguir criam a mesma configuração na CLI. Substitua os valores de marcador entre colchetes angulares. Observe o nome de destino na saída de `vserver iscsi show`; você precisará dele para verificar a conexão do host.

[source, console]
----

cluster::> vserver iscsi create -vserver a50-sql -target-alias a50-sql

cluster::> network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_1 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.134 -netmask 255.255.255.0
cluster::> network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_2 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.135 -netmask 255.255.255.0
cluster::> network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_1 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.136 -netmask 255.255.255.0
cluster::> network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_2 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.137 -netmask 255.255.255.0

cluster::> vserver iscsi show -vserver a50-sql
cluster::> network interface show -vserver a50-sql -data-protocol iscsi
----

====



NOTE: As LIFs iSCSI não migram durante um takeover. A alta disponibilidade é fornecida pelos caminhos para as LIFs do nó parceiro, portanto, sempre crie LIFs iSCSI em ambos os nós do par de HA.

[[step-5-review-the-volume-and-lun-settings]]
[[volume-settings]]
== Etapa 5: revise as configurações de volume e LUN

Analise as configurações de espaço e snapshot dos quatro volumes. O System Manager utiliza valores padrão adequados; as seguintes configurações são recomendadas para LUNs do SQL Server:

[cols="1,1,3"]
|===
| Contexto | Valor | Motivo 


| Garantia de espaço (volume) | `none` (fino) | A capacidade é consumida apenas quando os dados são gravados. 


| Reserva de espaço | `disabled` (fino) | LUN com provisionamento fino em um volume com provisionamento fino. 


| Alocação de espaço LUN | `enabled` | Habilita o SCSI UNMAP, permitindo que o espaço liberado no NTFS seja devolvido ao ONTAP e possibilitando que o host reaja corretamente quando o volume ficar sem espaço. 


| Política de instantâneo | `none` | Snapshots que não são consistentes com o aplicativo não servem para o SQL Server. Os backups são criados pelo NetApp Console Backup and Recovery. 


| Reserva do Snapshot | `0` % | O espaço do Snapshot é monitorado com o dimensionamento automático do volume. 


| Dimensionamento automático | `grow`, no máximo cerca de 130 % do tamanho do volume | Impede que o LUN fique offline quando os snapshots consomem espaço. 


| Eficiência de storage | ativado (padrão no AFF) | A desduplicação inline, a compressão e a compactação não têm impacto mensurável no desempenho do SQL Server. 
|===
Utilize os seguintes comandos para aplicar e verificar as configurações (mostradas para `sql_iscsi_1_data`):

[source, console]
----
cluster::> volume modify -vserver a50-sql -volume sql_iscsi_1_data -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 730GB
cluster::> lun modify -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1 -space-allocation enabled
cluster::> volume show -vserver a50-sql -volume sql_iscsi_1_* -fields aggregate,size,space-guarantee,snapshot-policy,autosize-mode
----

NOTE: Alterar `space-allocation` em uma LUN existente exige que a LUN esteja offline. Configure isso no momento da criação ou antes que o host se conecte à LUN.

.PowerShell

Os comandos a seguir colocam os discos NetApp online, inicializam-nos com GPT, criam e formatam um volume NTFS com tamanho de unidade de alocação de 64 KB em cada um e criam as pastas para o SQL Server.

[source, powershell]
----
PS C:\> $layout = @{ 520GB = 'E','data'; 250GB = 'F','log'; 150GB = 'G','tempdb'; 300GB = 'H','Log backup' }
PS C:\> foreach ($d in Get-Disk | Where-Object FriendlyName -like 'NETAPP*') {
          $l = $layout[[int64]$d.Size]
          Set-Disk -Number $d.Number -IsOffline $false
          Set-Disk -Number $d.Number -IsReadOnly $false
          Initialize-Disk -Number $d.Number -PartitionStyle GPT
          New-Partition -DiskNumber $d.Number -UseMaximumSize -DriveLetter $l[0] |
            Format-Volume -FileSystem NTFS -AllocationUnitSize 65536 -NewFileSystemLabel $l[1] -Confirm:$false
        }
PS C:\> 'E:\data','F:\log','G:\tempdb\data','G:\tempdb\log','H:\backup' | ForEach-Object { New-Item -ItemType Directory -Path $_ }
PS C:\> Get-Volume -DriveLetter E,F,G,H | Format-Table DriveLetter,FileSystemLabel,FileSystem,AllocationUnitSize,Size
----

CAUTION: Execute esses comandos somente se esses LUNs forem os únicos LUNs RAW conectados ao sistema. Se houver outros LUNs RAW conectados ao sistema, você precisará criar as pastas e formatar os volumes manualmente.

== Etapa 9: verifique a instalação

Crie um banco de dados de teste e verifique se seus arquivos de dados e de log estão nas NetApp LUNs e se os caminhos de armazenamento estão funcionando corretamente.

.Passos
. Abra a porta do SQL Server no firewall do Windows:
+
[source, powershell]
----
PS C:\> New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----
. Instale o SQL Server Management Studio (SSMS) a partir do link *Instalar as Ferramentas de Gerenciamento do SQL Server* no Centro de Instalação, ou no site da Microsoft.
. Inicie o SSMS e conecte-se à instância (`{host}` com autenticação do Windows. Crie um banco de dados de teste; seus arquivos de dados e de log padrão são  `E:\data` e  `F:\log`.
. Verifique a localização dos arquivos com T-SQL:
+
[source, sql]
----
SELECT DB_NAME(database_id) AS database_name,
       type_desc,
       name AS logical_name,
       physical_name,
       size * 8 / 1024 AS size_mb
FROM   sys.master_files
ORDER  BY database_id, type_desc;
----
. Verifique se a inicialização instantânea de arquivos está ativada:
+
[source, sql]
----
SELECT servicename, service_account, instant_file_initialization_enabled
FROM   sys.dm_server_services;
----
. Verifique o armazenamento a partir do host e do ONTAP:
+
[source, powershell]
----
PS C:\> Get-Disk | Where-Object FriendlyName -like 'NETAPP*' | Format-Table Number,FriendlyName,Size,OperationalStatus,PartitionStyle
PS C:\> mpclaim -s -d
----
+
[source, console]
----
cluster::> lun show -vserver a50-sql -fields path,size,mapped,state
cluster::> vserver iscsi session show -vserver a50-sql
cluster::> qos statistics volume latency show -vserver a50-sql
----
. Opcional: teste a alta disponibilidade. Execute uma carga de trabalho no banco de dados de teste e realize uma operação de takeover e giveback no ONTAP do nó que é proprietário do volume de dados (`storage failover takeover -ofnode <node>` / `storage failover giveback -ofnode <node>`). A carga de trabalho pausa por alguns segundos e continua; os bancos de dados permanecem online.


.O que vem a seguir
Proteja os bancos de dados com backups de snapshot consistentes com a aplicação. Para conhecer a arquitetura, o fluxo de trabalho de backup e os benefícios, consulte link:sql-iscsi-aff-overview.html#console["Proteção de dados com a NetApp Console Backup and Recovery"].



[[use-an-ontap-cli-script-to-configure-the-storage-in-one-pass]]
[[cli-script]]
== Use um script da CLI do ONTAP para configurar o armazenamento de uma só vez

O script a seguir contém a configuração de storage deste procedimento. Substitua os valores entre colchetes angulares antes de executá-lo.

[source, console]
----
# --- iSCSI service and LIFs ----------------------------------------------
vserver add-protocols -vserver a50-sql -protocols iscsi
vserver iscsi create -vserver a50-sql -target-alias a50-sql

network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_1 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.134 -netmask 255.255.255.0
network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_2 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.135 -netmask 255.255.255.0
network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_1 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.136 -netmask 255.255.255.0
network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_2 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.137 -netmask 255.255.255.0

# --- Initiator group -----------------------------------------------------
lun igroup create -vserver a50-sql -igroup sql-iscsi-1 -protocol iscsi -ostype windows -initiator iqn.1991-05.com.microsoft:sql-iscsi-1.sapcc.stl.netapp.com

# --- Volumes -------------------------------------------------------------
volume create -vserver a50-sql -volume sql_iscsi_1_data      -aggregate <aggr_node1> -size 560GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 730GB
volume create -vserver a50-sql -volume sql_iscsi_1_log       -aggregate <aggr_node2> -size 270GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 350GB
volume create -vserver a50-sql -volume sql_iscsi_1_tempdb    -aggregate <aggr_node2> -size 165GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 210GB
volume create -vserver a50-sql -volume sql_iscsi_1_logbackup -aggregate <aggr_node1> -size 325GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 420GB

# --- LUNs ----------------------------------------------------------------
lun create -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1           -size 520GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled
lun create -vserver a50-sql -path /vol/sql_iscsi_1_log/sql_iscsi_1_log_1             -size 250GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled
lun create -vserver a50-sql -path /vol/sql_iscsi_1_tempdb/sql_iscsi_1_tempdb_1       -size 150GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled
lun create -vserver a50-sql -path /vol/sql_iscsi_1_logbackup/sql_iscsi_1_logbackup_1 -size 300GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled

# --- LUN mapping ---------------------------------------------------------
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1           -igroup sql-iscsi-1
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_log/sql_iscsi_1_log_1             -igroup sql-iscsi-1
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_tempdb/sql_iscsi_1_tempdb_1       -igroup sql-iscsi-1
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_logbackup/sql_iscsi_1_logbackup_1 -igroup sql-iscsi-1

# --- Verification ----------------------------------------------------------
vserver iscsi show -vserver a50-sql
network interface show -vserver a50-sql -data-protocol iscsi
lun show -vserver a50-sql -fields path,size,ostype,space-allocation,mapped,state
lun mapping show -vserver a50-sql
vserver iscsi session show -vserver a50-sql
----

TIP: Distribua os volumes entre os agregados de ambos os nós, por exemplo, dados e backup de logs no nó 1, e logs e TempDB no nó 2. Isso utiliza os recursos de ambos os controladores.

== Use um PowerShell script para configurar o host em uma única etapa

O script a seguir contém a configuração completa do host deste procedimento. Execute-o em uma sessão do PowerShell com privilégios elevados; a parte de MPIO requer uma reinicialização.

[source, powershell]
----
# --- Part 1: iSCSI service and MPIO (restart required) ------------------------
Set-Service -Name MSiSCSI -StartupType Automatic
Start-Service -Name MSiSCSI
(Get-InitiatorPort | Where-Object ConnectionType -eq 'iSCSI').NodeAddress   # initiator IQN for the igroup
Install-WindowsFeature -Name Multipath-IO
Enable-MSDSMAutomaticClaim -BusType iSCSI
# Install NetApp Windows Host Utilities (MPIO support) now, then:
Restart-Computer

# --- Part 2: connect the iSCSI sessions (after the LUNs are mapped in ONTAP) ---
$initiatorIP = '192.168.175.44'
$lifs        = '192.168.175.134','192.168.175.135','192.168.175.136','192.168.175.137'
New-IscsiTargetPortal -TargetPortalAddress $lifs[0] -InitiatorPortalAddress $initiatorIP
$target = Get-IscsiTarget | Where-Object NodeAddress -like 'iqn.1992-08.com.netapp:*'
foreach ($lif in $lifs) {
    Connect-IscsiTarget -NodeAddress $target.NodeAddress -TargetPortalAddress $lif `
        -InitiatorPortalAddress $initiatorIP -IsMultipathEnabled $true -IsPersistent $true
}
Get-IscsiSession | Format-Table TargetNodeAddress,InitiatorPortalAddress,IsConnected,IsPersistent
mpclaim -s -d

# --- Part 3: disks, volumes and folders ---------------------------------------
$layout = @{ 520GB = 'E','data'; 250GB = 'F','log'; 150GB = 'G','tempdb'; 300GB = 'H','Log backup' }
foreach ($d in Get-Disk | Where-Object FriendlyName -like 'NETAPP*') {
    $l = $layout[[int64]$d.Size]
    Set-Disk -Number $d.Number -IsOffline $false
    Set-Disk -Number $d.Number -IsReadOnly $false
    Initialize-Disk -Number $d.Number -PartitionStyle GPT
    New-Partition -DiskNumber $d.Number -UseMaximumSize -DriveLetter $l[0] |
        Format-Volume -FileSystem NTFS -AllocationUnitSize 65536 -NewFileSystemLabel $l[1] -Confirm:$false
}
'E:\data','F:\log','G:\tempdb\data','G:\tempdb\log','H:\backup' | ForEach-Object { New-Item -ItemType Directory -Path $_ -Force }

# --- Part 4: firewall for SQL Server -----------------------------------------
New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----

NOTE: Execute cada parte separadamente. A parte 1 exige reinicializar o host, portanto as outras partes não continuarão após a reinicialização.


CAUTION: Execute os comandos da parte 3 somente se esses LUNs forem os únicos LUNs RAW conectados ao sistema. Se houver outros LUNs RAW conectados ao sistema, você precisará criar as pastas e formatar os volumes manualmente.
